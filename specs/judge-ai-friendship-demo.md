# 城市选择五角色体验桌

状态：已完成并验收，2026-09-13。范围：案例、桌友调度、桌内响应反馈、真实闭环验收。

## 依据与取舍

已核对产品沉淀 v1.3 / v1.4 的「好桌」「主持」「收桌」「第一次有人接」章节、README、桌内 Multi-Agent SPEC、轻松聊天改造计划及其浏览器验收记录。产品价值是不同经历产生新认识、安全分歧和被接住的感觉；案例不以模型数量、消息数量或固定结论作为成功标准。

本次按用户指定为评委 + 林夏、周砚、程野三位虚构专业讨论者 + 圆桌主持，共五个公开角色。常规产品的五个真人席位上限保持原合同。模拟身份在入口说明、成员资料可查；不是知乎真实用户资料，也不伪造知乎引用。

## 体验设计

- 题目：离开大城市，是逃避还是重新选择生活？
- 林夏：县城医生，从真实迁居经历、获得与代价出发。
- 周砚：产品工程师，从职业机会、关系网络与低成本试验出发。
- 程野：城市研究者，从住房、照护、公共服务与掌控感出发。
- 开场两句只铺设可讨论的差异，后续取决于评委实际发言。每条回复聚焦一个具体点，短句、有限追问，不轮流演讲，不代替评委下结论。
- 阶段小结保存已经提出的观点、仍存的分歧、下一问题，允许修改并回到原话；修正进入后续桌友上下文。收桌使用实际记录与个人贡献。

响应可视化沿用现有暗色聊天面板、Noto Sans SC 正文和苔绿辅助色（底色 #121917，正文 #f2eee5，次文 #a9bbae，分隔 rgba(242,238,229,.14)）。聊天流左对齐，正文 15px，状态 12px，圆角沿用 12px。仅一行「林夏正在输入」与轻点动画；整理小结时「正在整理」。状态由真实服务端任务开始/结束驱动，无伪进度、无后台 Agent 名、无推理过程。用户输入期间让路，失败提供重试，失联/取消/收桌后清除等待状态。尊重 reduced-motion 和键盘焦点。

## 数据与合同

- `backend/app/demo/cases/ai_friendship.json`：版本化案例与人物模板，仅后端私有人设进入模型。
- 现有 `JsonTableRepository`：每次创建独立 `table_id`，持久化成员、模拟来源、消息、状态、小结、纠偏、收桌；本地位置 `backend/data/judge-demo.json`，Git 忽略。
- `backend/.env.local`：密钥、模型、演示开关和持久化路径。仅后端读取。
- `POST /demo/sessions`：`participant_id / display_name / request_id` 创建独立体验；request_id 防止网络重试重复建桌。
- `GET /demo/cases/ai_friendship`：公开入口信息；关闭演示开关时不可用。
- `POST /demo/sessions/{id}/resume?participant_id=...`：恢复/失败重试；只允许体验者。
- `TableState.demo`：案例、owner、模拟成员 ID；旧桌省略。
- `participant_typing`：只携带 is_typing，不上传未发送草稿；服务端有效期避免永久等待。
- `participant_response_status`：table_id、participant_id、response_id、thinking/paused/failed/idle；临时状态不当作消息或持久历史。
- 已通过校验的模拟发言复用 `message_committed`，包含 turn_id 和 source；主持复用 `agent_action`。

## 调度与不变量

1. 后端决定谁说，模型只写这一位的回复。点名优先，其次相关经历、参与平衡。
2. 单桌有限任务，真人新消息使旧生成失效；输入中暂停发送，结束后合并最近上下文。
3. 一般一人接话，最多两位连续补充，然后给评委留时间；沉默续聊有限次，无无限自聊。
4. 模型不写桌状态；使用既有安全校验、幂等仓储和广播。不能通过前端冒充模拟角色。
5. 生成失败显示可恢复状态，不把固定套话伪装成模型回复。
6. 收桌、离桌、断线和服务关闭取消任务；重连恢复记录，不重播开场。
7. 总结原文优先，不能把个人立场写成全桌共识；JSON 失败有一次带校验反馈的修复机会，仍失败安全降级。
