# 桌内流程真实浏览器验收记录

日期：2026-09-09  
环境：前端 `127.0.0.1:5174`、后端 `127.0.0.1:8000`，通过 `corepack pnpm dev:stack` 联合启动；Edge/Codex 浏览器，覆盖 `546 × 558` 与 `1256 × 610` CSS px。

## 本次验收纠正的缺口

上一轮把 TypeScript、构建和后端脚本通过当成了桌内流程验收，遗漏了真实浏览器状态。这次实际复现并修复了三类问题：

- 授权事件后重复显示“等待完整桌状态”提示；
- 打开入席面板时对整张 3D 场景施加模糊，转场截图会变成一层糊紫色；
- 从桌内回到远景后仍携带 join 意图，重新进入 discovering 会自动再次靠近，导致流程跳转不稳定。

## 真实路径

使用后端创建的 `ui-acceptance-final` 桌，按用户路径执行：

1. 匹配页 → `坐下来看看` → 桌边预览 → `坐下来看看 →`；
2. 等待相机进入，确认 `坐下聊聊` 自动出现，且场景清晰、无全屏 `backdrop-filter`；
3. 填写开场表达、勾选授权、点击 `入席 →`；
4. 发送第二条消息，确认两条真人表达都进入消息流；
5. 打开 `聊天记录`，确认回放包含 2 条表达、状态节点和主持动作区域；
6. 打开 `阶段小结` → `生成小结`，确认 `仍待讨论 / 接下来` 有内容；
7. 点击 `修改`，提交自然语言修订，确认新 revision 和 `历史版本` 出现；
8. 从更多菜单执行 `收桌`，确认共享基线、个人收桌卡和返回桌单入口出现。

## 结果

- [x] 入席面板自动出现，表单可填写；
- [x] 入席后没有重复授权提示或错误通知；
- [x] 桌内 2 条消息均成功落桌，发送后输入框恢复空态；
- [x] 历史、阶段小结、自然语言修订和收桌均可完成；
- [x] 入席面板只压暗界面，不模糊 3D 场景；
- [x] 后端收桌状态为 `closed=true`、`phase=close`，回放为 2 条消息、8 个快照。

## 追加桌面回归

第二轮桌面截图暴露出首轮窄视口验收没有覆盖的两个 CSS 合同错误：

- 匹配页的蓝色弧线不是 3D 风线，而是 `.sea-page.product-entry::before` 绘制的超大装饰椭圆；现已删除。
- React 通过父级 `has-join-open` 控制入席面板，但桌面样式错误地依赖从未渲染的 `.join-sheet.is-open`，导致面板平移到视口外、只留下右侧白条；现已统一为 `.phase-seated.has-join-open .join-sheet`。

在 `1256 × 610` 桌面视口重新执行预览、进桌、填写、授权和入席：面板打开时位于视口内，入席后完全隐藏；页面 `scrollWidth` 等于视口宽度，蓝色伪元素计算值为 `content: none`，最终聊天输入与首条消息正常显示。
